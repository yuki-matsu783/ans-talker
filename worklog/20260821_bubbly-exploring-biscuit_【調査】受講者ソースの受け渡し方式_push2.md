# worklog: 【調査】受講者ソースの受け渡し方式（push2）

対象: issue #6 のflow-id 2-3〜2-4（人間のレビューを敵対的レビューで代替）の1周目・2周目
（2026-08-21）。
全体作業計画: `plans/bubbly-exploring-biscuit.md`
個別調査計画: `plans/【調査】受講者ソースの受け渡し方式.md`
push回数: 3（worklogの連番は push2。1周目の反映時にworklogを分けなかったため、ファイル名の
連番とpush回数が1つずれている）

## 試したこと

- ユーザーの「人間の代わりに敵対的レビューを入れて」という指示を、`adversarial-review` スキルの
  「人間による呼び出し」として扱い、flow-id 2-3 の位置で実施した。
- 1周目（実施回数 1/3）: 13件の指摘。10件を投稿、3件は上限・選別表により報告のみ。
- ユーザーの「もう一度レビュー」により2周目（実施回数 2/3）: 14件の指摘。10件を投稿、
  4件は報告のみ。**投稿分・報告のみの分をともに全件反映した。**

## うまくいったこと

- **同じ計画に対して、2周目でもまったく別の欠陥が出た。** 1周目は自己矛盾・依存関係の破綻を
  中心に、2周目は**実行するとどう壊れるか**を中心に指摘が出ている。とくに次の3件は、
  実施していたら実害が出ていた。
  - `git fetch --depth 1 origin refs/pull/<n>/head` を**cwdで実行すると、このリポジトリの
    PR #7 のheadを取得して「案Aは成立した」と誤結論する**。成立条件を `headSha` との一致へ
    変え、一時ツリーを作る完全な手順へ書き直した。
  - `gh auth setup-git` は `~/.gitconfig` を書き換えるため、**受け入れ条件2の検証環境
    （git到達不可）そのものを到達可能側へ変えてしまう**。`git -c credential.helper=...` の
    その場限りのオーバーライドへ変更した。
  - GitHub側の演習環境として**このリポジトリのPRを流用する案**は、`answer-talker` 手順9が
    投稿まで行うため、レビュー中の自分のPRへ演習レビューが投稿される事故そのものだった。
- **必然的な後退を1件見つけられた（2周目の最重要）。** `answer-talker-spoiler-check.sh` の
  禁止語は `正解の識別子 − 受講者diffに現れる語 − …` であり、材料は `.files[]` の
  `patch, path, oldPath` から作られる。したがって issue #6 の目的である「hunkに現れない
  受講者ファイルに基づく指摘」は、**その識別子がdiffに現れないため差し引かれず、正解側に
  同名の識別子があれば必ず drop される**。受講者ソースを渡した瞬間、**新しく見えるように
  なったものについての指摘だけが選択的に落ちる**。論点5を「任意の見直し」から
  「本変更に伴う必須の追随」へ格上げした。
- **`use_target_repo` は `git` には効かない**（`GH_REPO`/`GITLAB_REPO`/`GITLAB_HOST` の
  export であり、`git clone`/`git fetch` はこれらを参照しない）。前提として引き継いだまま、
  案Aのclone URLをどう決めるかが論点に無かった。`--repo` が `owner/repo` 形式・省略のとき
  `host` が空になるため、self-hosted GitLab では URL を組み立てられない可能性がある。

## ダメだったこと・気づき

- **1周目の修正が、2周目で「依存先が移動しただけ」と指摘された。** 論点4・5の着手条件を
  「方式決定後」から「両案について洗い出す」へ直したが、論点5の案B側は「論点3で決めた範囲」に
  依存したままで、論点3が範囲を絞るのはフェーズ3だった。**候補a/b/cそれぞれについて1行ずつ
  出す**形へ固定して閉じた。
- **検証コマンドが「表示するだけ」で判定していなかった。**
  `for t in ...; do printf ... "$(bash "$t" | tail -1)"; done` は `failures=1` が出ていても
  読み飛ばせば通る。`case` で `failures=0` 以外を数え、`NG=<件数>` を出す形へ変更した。
- **`get_mr_unresolved_comments 7` の出力は3474行あり、そのまま表示すると
  `Error: writing output failed: Invalid argument` で落ちる。** 一時ファイルへ落としてから
  `grep -n` で threadId と指摘タイトルの行番号を突き合わせた。なお threadId は
  `PRRT_kwDOT-fGt86bHFI-` のように**ハイフンを含む**ため、`grep -o` の文字クラスを
  `[A-Za-z0-9_]*` にすると全件が同じprefixに潰れて「ユニーク1件」に見える。
- **`$TMPDIR` は git bash で未定義**（`set -u` 配下で `unbound variable`）。スクラッチ
  ディレクトリのパスを明示的に変数へ入れた。
