調査結果の訂正（設計に影響する）

MR番号だけでは「どのリポジトリのMRか」が決まらない

調査結果では「add_mr_inline_comments はMR番号を引数で取るので他人のMRにもそのまま使える」と書いたが、 誤りだった。gh / glab は 対象リポジトリをカレントディレクトリのgitリモートから解決する。 放置すると「自分のリポジトリのMRを読み、そこへ投稿する」という壊れ方をする。

問題（実機で確認）

$ gh api "repos/{owner}/{repo}" --jq '.full_name'
yuki-matsu783/ans-talker   # ← cwd のリポジトリ

$ glab api "projects/:id"
ERROR Unable to expand placeholder in path:
none of the git remotes configured for this
repository correspond to the GitLab instance

解決（実機で確認）

$ GH_REPO="cli/cli" gh api "repos/{owner}/{repo}"
cli/cli

$ GITLAB_REPO="root/issue45-verify" \
    glab api "projects/:id"
root/issue45-verify

この方式なら既存の Provider.sh / Github.sh / Gitlab.sh を1行も変えずに別リポジトリを対象にできる。 adversarial-review が使う共通コードに手を入れずに済む点で、 引数追加案（広範囲に波及）・cwd移動案（受講者リポジトリのcloneが必要）より優れる。 なお glab api には -R/--repo フラグが無いため、環境変数が唯一の統一手段。

D2・D3. 関数とスクリプトのインターフェース

D2. get_mr_changed_files <MR番号>

  • 名前は get_mr_diff にしない。既存の get_mr_diff_url は「URLを組み立てるだけ」で、似た名前で中身が違う3兄弟になる
  • 返却はstdoutへJSON1つ（Provider.shの全関数と同じ規約）。サイズ対策は「呼び出し側が必ずファイルへリダイレクトする」規約で担保する
  • additions/deletions はGitLabが返さないので diff本文から算出
  • truncated は GitHub＝patch欠落、GitLab＝too_large と collapsed の論理和
  • truncatedFiles/capped が立ったら必ず報告（無言で切り捨てない）

D3. answer-talker-reference.sh

  • サブコマンド方式（resolve / cleanup）。後始末を手順書の明示的な1ステップとして書けるほうが漏れにくい
  • ローカルはcloneしない。URLのみ --depth 1 --single-branch --no-tags
  • cleanup は冪等。任意のパスを rm -rf しないため、一時ディレクトリ配下かを検証する
  • cloneの失敗をパイプで潰さない（調査で実際に踏んだ）
  • MSYS_NO_PATHCONV は export しない。認証は扱わない

D4. サブエージェントの観点 — 「指摘しない条件」を各行に併記する

観点指摘する指摘しない
責務の分割単位1ファイル/1関数が複数の役割を抱えている分け方が正解と違うだけで、役割は分かれている
層・依存の向き依存が逆向き・循環している層の名前や粒度が違うだけ
命名・配置・エラー処理一貫していない流儀が正解と違うが、内部で一貫している
正解が避けている作り重複・密結合・ハードコード正解に無い作りだが、弊害が説明できない

「正解と違う」だけでは指摘の理由にならないことを、見出しの注意書きではなく各行の列として書く（注意書きは読み飛ばされる）。

悪い書き方

「UserRepository を切り出すべき」

良い書き方

「このファイルはHTTPの受け口とデータ永続化の2つの役割を持っている。片方が変わるともう片方を読み直す必要があるので、永続化の関心を別の単位へ分けられないか」

D5. ネタバレ検査 — 誤検知の側へ倒す

禁止語 = (正解ファイルの識別子) − (受講者diffに現れる語) − (除外語) − (3文字以下)
混入   = findings本文に、禁止語のいずれかが単語境界で現れる
  • 識別子は分割しない（snake_case をバラすと user が禁止語に入り実用にならない）
  • 受講者diffの語を引くのが誤検知を減らす主な働き
  • 除外語はスクリプト内の定数（演習ごとに変わらない。外部ファイルにすると「用意しないと動かない」失敗経路が増える）
  • 大文字小文字は区別する
  • 落とした finding だけを除外し、残りは通す（全体中止にしない）
  • 落とした件数と反応した語を必ず返す。この方針は「指摘が落ちすぎて何も出ない」壊れ方をするため、可視化が無いと気づけない
  • kept が0なら投稿しない
  • 単体テスト12ケース（部分文字列・境界・0件・日本語・大文字小文字）
