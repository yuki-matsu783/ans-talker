### 指摘 #4 への対応（`ATR_*` は環境変数ではない）

旧記述は「除外語リストは定数」とだけ書いており、計画の表には「`ATR_*` 環境変数」と書いていた。
**実装を確認したところ、`ATR_*` はすべて `readonly` の定数**で、利用者が設定するものではない。
節を書き直し、次の3つを分けた。

1. **定数**（`ATR_STOPWORDS` / `ATR_MARKER` / `ATR_SUBMISSION_MARKER` / `ATR_EXCLUDE_DIRS` /
   `ATR_DEFAULT_*`）— 変えるにはスクリプトを編集する。
2. **コマンドラインオプション**（`--max-size-kb` / `--max-fetch-files` / `--max-list-files` /
   `--timeout-sec`）— 既定値つきの表として載せた。**利用者が上限を変える口はこちらである。**
3. **`ATR_HTTP_TIMEOUT_SEC` だけは環境変数**だが、これは `--timeout-sec` の値を子プロセスへ
   渡すための内部的な受け渡しであり、設定項目ではない旨を明記した。

### 既存DDRの扱い（計画で保留していた判断）

- **DDR 0047 に `status: superseded` を付けない。** 0047 が決めたのは「位置指定は投稿直前に
  プロバイダごとの制約へ合わせて縮退させる」「findingsのスキーマはプロバイダ非依存に保つ」
  という**方針**であり、0064 はそれを維持したまま**実装の置き場所だけを変えた**。0047 の本文が
  当時の関数名で書かれているのは記録として正しい。**無効化ではなく詳細化**である。
- **DDR 0061 も無効化しない。** 0065 は材料を広げるが、それは**差し引く量を増やす**だけなので
  禁止語は減りこそすれ増えない。効くのは誤検知が減る方向のみで、0061 が守ろうとした
  「見逃しより誤検知を許容する」非対称はそのまま保たれる。

### 検証3の期待値が誤っていた

計画には「`github_filter_findings_by_valid_lines` は **1件**（issue #77 の表）であること」と
書いていたが、**実際は2件が正しい**。issue #6 のエントリが「この関数を削除した」と書く以上、
そこにも関数名が現れるためである。計画を書いた時点では、エントリの中身がまだ決まっていなかった。

**件数では、守りたい不変条件を表現できない。** 守りたいのは「issue #77 の表の行が変わって
いない」ことであって、文書全体での出現数ではない。件数の代わりに、**diffに削除行が無いこと**で
確認した。

```
git diff -- .claude/docs/spec/adversarial-review.md | grep -c '^-.*github_filter_findings_by_valid_lines'
→ 0（この関数名を含む行は1行も削除されていない）
```

こちらは**エントリを何行書き足しても影響を受けない**。件数による検査は、文書が育つと必ず
期待値の更新を要求してくるため、point-in-time記録の保護には向かない。

### 検証5が実際に拾ったもの

新設した検証5は、2つの誤りを見つけた。

1. **手順番号の作り話。** specの全体像の図を書くとき、受講者ソースの取得が入ったことで
   「手順4以降が1つずつ後ろへずれた」と書いた。**実装は番号をずらさず `手順3b` を使っている。**
   SKILL.md の見出しを機械的に列挙して気づき、図と説明を実態へ合わせた。
2. **`reason` の実例の漏れ。** specに載せた `reason` の例に `head-sha-unavailable` が
   無かった（実装には存在する）。報告（手順11）でそのまま人間の目に触れる文字列なので追加した。

**どちらも「実装を見ずに書いた」ことが原因**であり、指摘 #5 が問題にしていた形そのものだった。
