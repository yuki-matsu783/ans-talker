# 0040. 個別計画には結果を書かず、実施結果は `reports/` 配下のmdへ分離する

## 背景

issue #87。flow-id 2-6 は「調査を実施し、結果を**個別調査計画**・worklogに記録する」と定義されて
おり、実施結果の本文を計画ファイルへ追記する運用になっていた。issue #77 のフェーズ2で実際に
`plans/【調査】〜.md` の「## 調査結果」節へ結果を追記したところ、レビューで分離の指示があり
`reports/…md` へ移すことになった。

同居させると次の3点が問題になる。

1. レビュー時に「合意した計画」と「その後の結果」の区別がつかない。
2. 計画としての差分（レビュー往復で計画のどこが変わったか）が、結果の追記に埋もれる。
3. ライフサイクルが食い違う。計画は合意のスナップショットとして固定されるべきものだが、
   結果はpushのたびに書き換わる。

一方 `reports/` は、issue #58 以降「報告を視覚的に分かりやすくまとめた自己完結HTML」に限定されて
おり、markdownの報告を置く前提が無かった。

## 決定

**個別計画（`plans/【*】〜.md`）には「これから何をするか」だけを書き、実施結果は
`reports/日付_<全体計画名>_<内容を簡潔に>.md` へ記録する。**

- `reports/` にはmdとhtmlを**併存**させる。**mdが結果の正文、htmlはその視覚化**である。
- mdの寿命は既存の `reports/` htmlと同じ（タスク単位。flow-id 5-1で `plans/` `worklog/` と
  まとめて削除する）。
- frontmatterの `type` は `report` とする。
- **見出し構成は規定しない。** 記述の型（見出し構成）のテンプレート化はissue #54の担当であり、
  本決定が定めるのは「どこへ書くか」だけである。

## 却下した案

### 案A: 計画ファイル内で「## 計画」「## 結果」の節を分ける

同一ファイル内の節分割で区別する案。**却下**。上記の問題1（レビューでの区別）は多少緩和されるが、
問題2（計画の差分が結果の追記に埋もれる）・問題3（ライフサイクルの不一致）はファイルが同じである
限り解消しない。gitの差分はファイル単位で提示されるため、レビュアーは結局「どの節の変更か」を
毎回読み分けることになる。

### 案B: 結果はworklogに一本化し、`reports/` mdを新設しない

`worklog/` は既に存在し、実施内容の記録先として機能している。**却下**。worklogは
「何を試した／うまくいった／ダメだったか」という**試行錯誤の過程**のログであり、読み手は
「どう辿り着いたか」を知りたいときに読む。一方、レビュアーが flow-id 2-8/3-8/4-8 で読むべきなのは
**結論とその根拠**であり、関心が異なる。両者を1ファイルに混ぜると、worklogが「頻繁に書き足す
作業ログ」であることをやめてレビュー用に整形され続けることになり、worklogの利点（気軽に書ける）が
失われる。

### 案C: 結果はhtmlのみとし、mdを作らない

`reports/` に既にあるhtmlへ結果を書けば、新しい置き場所を増やさずに済む。**却下**。htmlは
差分レビューに向かない（マークアップの変更と内容の変更が混ざり、コメントを行に紐付けにくい）。
また、flow-id 4-6でspec/ddrへ反映する際の入力としても、markdownの方が扱いやすい。
htmlは視覚的な把握のための派生物と位置づけ、正文はmdとする。

### 案D: `.mrworkflow.json` に `reportsMdDir` を追加してmdとhtmlの置き場所を分ける

**却下**。両者は同じライフサイクル（flow-id 5-1でまとめて削除）を持ち、同じ内容の別表現である。
ディレクトリを分けると `get_branch_work_files`・flow-id 5-1の削除対象・`.gitignore` の
いずれもが二重定義になり、設定項目の増加に見合う利点が無い。同一ディレクトリで拡張子により
区別する。

## 影響

- `.claude/skills/issue-mr-flow/SKILL.md`（flow-id 2-6/2-9/3-6/3-9/4-6/4-9/5-1、「計画と実施結果の
  分離」節の新設）
- `.claude/rules/docs-workflow.md`（運用表へ `reports/…md` の行を追加、個別計画の行へ
  「結果は書かない」旨を追記）
- `.claude/rules/directory-structure.md`（`reports/` の記述をmd/html両方を含む形へ更新）
- `.claude/rules/markdown-frontmatter.md`（「typeの値」表へ `report` を追加）
- `index.md`・`.claude/skills/canvas-report/SKILL.md`（同上の反映）

スクリプト側の変更は不要である。`Provider.sh` の `get_branch_work_files`・flow-id 5-1の削除処理は
いずれも `reports/` を**ディレクトリ単位**で対象にしているため、拡張子が増えても動作が変わらない。
