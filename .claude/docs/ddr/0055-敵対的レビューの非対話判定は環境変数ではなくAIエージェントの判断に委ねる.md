# 0055. 敵対的レビューの非対話判定は環境変数ではなくAIエージェントの判断に委ねる

## 背景

issue #106。DDR 0045の決定4は、対話セッションでは敵対的レビューの自律起動を禁止し、
非対話セッション（`AUTOMATION=1`）でのみ許すと定めた。しかし `AUTOMATION` は「運用側が
明示的に設定する片方向の契約」として定義されただけで、実際にこれを設定する経路（CI環境変数の
自動注入、起動スクリプトでの設定等）はこのリポジトリのどこにも実装されていなかった
（`.claude/docs/spec/adversarial-review.md` の未決定事項に「非対話環境で `AUTOMATION=1` が実際に
設定されるかは未検証」と記されたまま残っていた）。

結果として、この判定は非対話セッションであっても常に「対話モード」と判定され続け、
判定ロジックとして意味を成していなかった。効果のない判定を残すよりも、判定手段そのものを
見直す必要がある。

## 決定

- **`AUTOMATION` 環境変数による判定（旧SKILL.md 手順1）を廃止する。** 判定用のbashコードと
  番号付きの手順としては持たない。
- **非対話セッションかどうかは、AIエージェント自身が実行環境の性質（人間とのレビュー往復が
  成立するか）から判断する。** 環境変数のような機械的な信号ではなく、対話の有無・応答を
  待てるかどうかという文脈から判断する。
- **判断に迷う場合は対話モード（起動禁止）を既定とする。** DDR 0045が採用した「未設定＝対話
  モード」という安全側フォールバックの思想は維持し、判定手段だけを差し替える。
- **DDR 0045の決定4のうち、起動を許す／禁じる方針（対話セッションでは禁止・非対話セッションのみ
  許す）自体は変更しない。** 変わるのは判定手段のみであるため、DDR 0045の `status` は変更しない
  （他の決定1〜3・5〜7は引き続き有効）。

仕様の詳細は
[.claude/docs/spec/adversarial-review.md](../spec/adversarial-review.md)「起動ポリシー」節を正とする。

## 却下した案

- **`AUTOMATION` を実際に設定する経路を新設する**（例: CI環境変数として注入するsetupスクリプトを
  書く）。しかしこのリポジトリの「非対話セッション」はClaude Code on the webのようなリモート実行
  環境全般を指し、実行基盤側の環境変数注入に依存させると、対応していない実行環境では引き続き
  判定できない。加えて、環境変数を新設しても「実際に設定されるか」を機構側で検証する手段が無く、
  DDR 0045時点から指摘されていた未検証の懸念（`.claude/docs/spec/adversarial-review.md`
  「未決定事項・懸念点」）が形を変えて残るだけになる。AIエージェント自身が実行環境の性質を
  都度判断するほうが、追加の実行基盤側の対応を必要とせず確実である。

- **判定そのものを廃止し、非対話セッションでも常に対話モード扱いとする**（＝非対話セッションでの
  自律起動を諦める）。実装が最も単純になる。しかしこれはDDR 0045決定4が解こうとした「人間の
  レビュー往復を待てない実行環境でレビューの空白を埋める」という目的を放棄することになり、
  issue #106の期待する動作（判定手段の置き換え）とも異なる。
