# 0041. チャットで受けたレビュー判断はAIエージェント自身がMRの通常コメントへ記録する

## 背景

`.claude/skills/issue-mr-flow/SKILL.md` の `comments` サブコマンド手順3は「ユーザがプロンプトに
おいて指摘を行った場合は、MRにコメントすることを促す」という規定で、**人間に促すだけ**であり
AIエージェント自身は何も記録しなかった。

issue #48 のフェーズ4（PR #49）で、AIエージェントが判断を仰いだ3点すべてがチャットで回答され、
MR上には未解決スレッド0件のまま判断の記録が一切残らなかった。判断とその理由は計画ファイル
（`plans/`）へ「レビュー結果」として追記されていたが、`plans/` はflow-id 5-1で削除されるうえ
squash mergeによりmainにも残らないため、PR画面からは経緯を一切辿れない状態だった（issue #50）。

AIエージェントが自発的に上げた論点には、そもそも紐づくレビュースレッドが存在しない。したがって
「回答がチャット側に来る」ことは例外ではなく、この経路の既定である。

## 決定

**チャットでレビュー判断を受けたら、AIエージェント自身が `add_mr_comment`
（PR/MRの通常コメント）でMRへ記録を投稿する。**

- **実施主体はAIエージェント**とする。人間へ促す規定は、実行を保証しない（issue #48で実際に
  記録が残らなかった）ため、AIエージェントの実施事項へ変更する。
- **記録先は通常コメント**とする。レビュースレッドではないため、`get_mr_unresolved_comments` の
  未解決件数には現れず、「レビュー完了合図の確認」の判定を狂わせない。
- **記録の単位はレビュー往復1回につき1コメント**とし、その往復の修正を済ませた後
  （`comments` サブコマンド手順5）に投稿する。該当する判断が無い往復では何も投稿しない。
- **残す／残さないの基準**を定義する。判断軸は「後から『なぜこうなっているのか』をPR/MR画面
  だけで説明できるか」であり、迷った場合は残す側へ倒す。基準の全文は
  `.claude/skills/issue-mr-flow/SKILL.md`「チャットで受けたレビュー判断の記録」節が正である。
- **署名は `reply` サブコマンドと同じ規約**とし、本文の先頭に `Claude Codeより:` を付ける
  （DDR 0004）。記録コメントも `reply` と同じくAIが書いた文章であり、投稿者アカウントを分離
  できないという前提も同じであるため、規約を分ける理由が無い。

## 却下した案

- **現状維持（人間に促すだけ）**: 実装コストはゼロだが、促しは実行を保証しない。issue #50が
  問題にしている状況そのものであり不採用。
- **チャットでのやり取りをすべて記録する**: 基準を設けずに全発言を残せば取りこぼしは無くなるが、
  「OK」「次はpushして」といった中身の無い合図までMR画面へ並び、人間のレビューコメントが
  埋没する。記録を残す目的（後から経緯を辿れること）に対して逆効果のため不採用。基準を定義し、
  該当するものだけを残す方式を採った。
- **レビュースレッドへの `reply` で代用する**: 既存機能をそのまま使えるが、AIエージェントが
  自発的に上げた論点には紐づくスレッドが存在しないため、記録先が無く成立しない。スレッドが
  存在する指摘については従来どおり `reply` が正であり、記録コメント側では二重に残さない。
- **MR description（`describe`）へ追記する**: PR画面の一番上に常に見える利点はあるが、
  descriptionは `describe` サブコマンドが「現在の計画・実装状況」の最新スナップショットとして
  **上書き**する対象であり、時系列の判断ログを載せると次の更新で消える。役割が衝突するため不採用。
- **`plans/` への追記のみ（現状の実態）**: flow-id 5-1で削除され、squash mergeによりmainにも
  残らない。issue #50が指摘した問題そのもののため不採用。ただし計画ファイルへの追記自体を
  禁止するものではなく、MRコメントによる記録がそれと併存する。
- **判断1件につき1コメントを投稿する**: 判断と投稿が1対1で対応し取りこぼしを検知しやすいが、
  レビュー往復が重なるとMR画面が記録で埋まる。往復単位でまとめる方式を採った。

## 影響範囲

`.claude/skills/issue-mr-flow/SKILL.md`（新節・`comments` 手順・フロー表6行・MCP読み替え表）、
`.claude/docs/spec/issue-mr-workflow.md`（「チャットで受けたレビュー判断の記録（issue #50）」節）。
`Provider.sh` の関数（`add_mr_comment`）は既存のまま変更しない（本文を自由文として受け取る
設計であり、署名の付与は呼び出し側の責務という DDR 0004 の切り分けと一貫する）。
