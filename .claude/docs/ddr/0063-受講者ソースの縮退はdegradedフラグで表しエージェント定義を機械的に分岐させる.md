# 0063. 受講者ソースの縮退はdegradedフラグで表しエージェント定義を機械的に分岐させる

## 背景

issue #6 が直そうとした不具合そのものが、「**渡していないものを『読んでよい』と定義に書いて
いた**」という定義と実装の食い違いだった。`.claude/agents/answer-talker-reviewer.md` の
「読んでよいもの」には「受講者の変更ファイルの中身」と書かれていたが、実際には渡していなかった。

受講者ソースを渡すようにしても、DDR 0062 のとおり**取得できないことがある**（段3）。
このとき定義へ無条件に新しい意味を書くと、
**issue #6 が問題にしたのと同型の不一致を、自分の手で新たに作る**ことになる。

さらに、縮退は「受講者ソースが読めない」だけでは終わらない。同じ実行の中で
`mapping.submissionOnly` の意味と、ネタバレ検査で差し引く材料の範囲も同時に変わる。

| | 段1・段2（取得できた） | 段3（取得できない） |
|---|---|---|
| 読めるもの | 受講者ソース全体＋`patch` | `patch` のみ |
| `mapping.submissionOnly` | 正解に無いファイル | 今回のMRで追加したファイル |
| ネタバレ検査で差し引く材料 | 受講者ソース全体の語 | 受講者diffの語 |

**3つが連動して変わる**ため、サブエージェント側に「今どちらなのか」を推測させる形にはできない。

## 決定

1. **縮退の状態を入力JSONの `degraded`（真偽値）で表し、サブエージェント定義は
   その値だけで読み方を決める。** 「渡されたかどうか」をサブエージェントが自分で判断しない。

2. **連動して変わる2つも、それぞれ専用のキーで返す。** `answer-talker-map.sh` は
   `scope`（`full` / `diff`）、`answer-talker-spoiler-check.sh` は
   `materialScope`（`full` / `diff`）を返す。**呼び出し側が自然言語で伝え直さない。**
   伝達経路が「機械可読なキー」と「プロンプトの地の文」の2つあると、必ずどこかで食い違う。

3. **`degraded: true` のときの制限を、定義へ明示的に書く。**
   - 「〜が無い」「どこにも定義されていない」という**不在を根拠にした指摘を書かない**
     （見えていないだけかもしれない）。
   - 責務の分割単位の指摘の `confidence` を `high` にしない。
   - **指摘の件数が減るのは正しい結果である。** 見えない分を推測で埋めない。

4. **`degraded: true` のときに、サブエージェントが受講者ソースを別の手段で取りに行くことを
   禁じる。** 取得の可否は呼び出し側が既に判定しており、サブエージェントは読み取り専用である。

5. **成功時と縮退時でキー集合を変えない。** 段3でも `stage` / `root` / `tmpdir` / `fileCount` /
   `files` / `truncated` / `degraded` / `reason` を同じ形で返し、値だけを変える
   （`root: null`、`files: []` 等）。呼び出し側にキーの有無で分岐させない。

## 却下した案

- **定義へ無条件に「受講者ソース全体を読んでよい」と書く。** issue #6 が直した不一致を、
  縮退時に再生産する。しかも今度は**実行ごとに真偽が変わる**ため、以前より質が悪い。
- **取得に失敗したらスキル自体を中止する。** 縮退という概念を持たずに済むが、
  hunkだけでもレビューは成立する（issue #6 以前はそれが通常運転だった）。
  取得の失敗が**レビューできない理由になってしまう**のは、可用性の後退である。
- **`degraded` を持たせず `root` が `null` かどうかで判断させる。** 判定は可能だが、
  「なぜ `null` なのか」（サイズ超過か・取得失敗か・そもそも試していないか）が読み取れない。
  `reason` と対にして意味を持たせるほうが、報告（手順11）にもそのまま使える。
- **`scope` / `materialScope` を持たせず、呼び出し側がプロンプトへ「全体を渡しました」と
  書く。** 実装が1箇所変わったときに、プロンプトの地の文だけが古いまま残る。
  **食い違っても誰も気づかない形**であり、issue #6 と同じ失敗の作り方である。
- **`--submission-root` に存在しないパスが渡されたら黙って無視する。** 実装の初期案だったが、
  無視すると `materialScope` が `diff` へ戻り、**広げたつもりで広がっていない状態が
  「正常応答」として返る**。エラーにして止める形へ変えた。
