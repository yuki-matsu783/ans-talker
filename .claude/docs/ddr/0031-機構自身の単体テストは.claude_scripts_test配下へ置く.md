# 0031. 機構自身の単体テストは`.claude/scripts/test`配下へ置く

## 背景

このリポジトリは issue駆動MRワークフロー機構（`.claude/` 一式・`.mrworkflow.json`・issue
テンプレート等）のテンプレートであり、`apply-mr-workflow-to-project` スキルの
`.claude/skills/apply-mr-workflow-to-project/scripts/sync-assets.sh` が、他プロジェクトへ
AIアセットを配布する。配布対象は `.claude/` `.gemini/` `.github/` `.gitlab/` の4ディレクトリと、
ルート直下の数ファイル（`.mrworkflow.json` / `AGENTS.md` / `GEMINI.md` / `CLAUDE.md` /
`HANDOFF.md` / `index.md`）である。

機構自身の単体テスト4本（`test_extract_frontmatter.sh` / `test_update_handoff_progress.sh` /
`test_usage_tracking.sh` / `test_vcs_provider.sh`）は、issue #6 のbash化以降リポジトリ直下の
`tests/` に置かれていた。この位置はどちらの意味でも配布と噛み合わない。

- 配布対象に含まれないため、**導入先ではテストが付いてこない**。機構のスクリプトだけが配られ、
  それが壊れていないことを確かめる手段が同梱されない。
- かといって配布対象へ加えると、**導入先プロジェクト本体の `tests/` と同じ場所を取り合う**。
  多くのプロジェクトはリポジトリ直下の `tests/` を自分のテスト置き場として使っており、
  そこへ機構のテストを混ぜ込むことになる。

## 決定

**機構自身の単体テストは `.claude/scripts/test/`（`.claude/scripts/src/` の兄弟）に置く。**
4本を `git mv` で移動し、リポジトリ直下の `tests/` は廃止した。

この位置には次の性質がある。

- **配布に何も足さなくてよい。** `sync-assets.sh` は `.claude/` 配下をそのままコピーするため、
  スクリプトの変更なしにテストが導入先へ同梱される。配布対象の一覧に「例外的にルート直下の
  このディレクトリも」という項目が増えない。
- **導入先の `tests/` と衝突しない。** 機構のものは `.claude/` の中に閉じ、導入先プロジェクトは
  リポジトリ直下の `tests/` を自由に使える。
- **テスト対象との距離が近い。** 4本のうち3本は `.claude/scripts/src/` および
  `.claude/hooks/lib/` のスクリプトを `source` して関数を直接呼ぶ方式であり、テスト対象と
  同じ配布単位に同居する方が対応関係が読み取りやすい。

移動に伴う実装上の変更は、各テストの `repo_root` 算出（`$script_dir/..` →
`$script_dir/../../..`）と、冒頭コメント・`shellcheck source=` の相対パスのみである。
テストの本体（アサーション）は1件も変更しておらず、移動前後で `passed` の内訳
（17 / 15 / 33 / 36 = 101件）が完全に一致することを確認した。

## 却下した案

- **`tests/` のまま `sync-assets.sh` の配布対象に加える**: 上記のとおり導入先プロジェクト本体の
  `tests/` と場所を取り合う。ファイル名が `test_<対象>.sh` で衝突しなかったとしても、導入先の
  テストランナーが `tests/` を一括で拾う構成（pytest・go test・jest等）では、機構のbashテストが
  導入先のテスト実行に紛れ込む。配布物が導入先の既存ディレクトリの中身を書き換えるのは、
  `.claude/` 配下に閉じるという配布の設計方針からも外れる。
- **`tests/` のまま配布しない（現状維持）**: 導入先で機構のスクリプトを改変したときに、
  壊していないことを確かめる手段が無い。`extract-frontmatter.sh` や
  `update-handoff-progress.sh` は導入先でも実際に実行されるスクリプトであり、テストが
  同梱されている価値は小さくない。
- **`.claude/tests/`（`scripts/` の外）に置く**: 配布に載る点は同じだが、テスト対象である
  `src/` から1階層離れる。`.claude/scripts/` を「AIエージェントが実行するスクリプト一式」の
  単位と捉え、その中を `src/`（本体）と `test/`（テスト）に分ける方が対応関係が明快と判断した。
- **`.claude/scripts/tests/`（複数形）にする**: `src/` と語形を揃え単数形の `test/` を採った。
  意味の違いは無く、`src/` の兄弟として並べたときの見た目のみの判断である。
