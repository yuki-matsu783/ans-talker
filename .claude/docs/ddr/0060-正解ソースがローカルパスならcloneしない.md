# 0060. 正解ソースがローカルパスならcloneしない

## 背景

issue #1。`answer-talker` は正解ソースを2つの形態で受け付ける必要がある
（受け入れ条件）——**別リポジトリのURL**と**ローカルディレクトリ**である。

素直な設計は「どちらも一時ディレクトリへ `git clone --depth 1` して、読む場所を1つに揃える」
だった。取得後の扱いが一本化され、後始末も「作った一時ディレクトリを消す」だけで済む。

しかし実機で確認したところ、この前提が2つとも崩れた。

- **`--depth 1` は局所cloneでは無視される。** `warning: --depth is ignored in local clones` が
  出て、浅くならない。正解リポジトリの全履歴を複製することになり、shallow cloneを選んだ意味が
  失われる。
- **素のディレクトリ（gitリポジトリでない）はそもそもcloneできない。** 講師が正解を単なる
  フォルダとして持っている場合、この経路は成立しない。ローカルディレクトリを受け付けるという
  要件は、gitリポジトリであることを前提にしていない。

## 決定

**ローカルパスはcloneしない。読み取り専用でそのまま使う。** shallow cloneするのはURLのみとする。

`answer-talker-reference.sh` は `resolve` の返却でこの違いを表現する。

| 指定 | `kind` | `root` | `cleanup` | `tmpdir` |
|---|---|---|---|---|
| URL | `url` | 一時ディレクトリ内のclone先 | `true` | 一時ディレクトリ |
| ローカルパス | `local` | 与えられたパスの絶対パス | `false` | `null` |

- **後始末の対象は「自分が作った一時ディレクトリだけ」に限定される。** `cleanup:false` は
  「消してはいけない」を明示的に表す。ローカルパス指定時に消してしまえば、講師の手元の正解が
  失われるという取り返しのつかない事故になる。
- **`cleanup` は冪等**で、`resolve` が一時ディレクトリ直下へ置いたマーカーファイル
  `.answer-talker-reference` がある場合しか削除しない。渡された任意のパスを削除しないための
  安全弁でもある。
- ローカルパス指定時は**正解ディレクトリを書き換えない**（サブエージェントは読み取り専用）。
- ローカルパスに `--ref`（ブランチ・タグ）は指定できない。cloneしない以上、意味を持たないため。

あわせて、URLのclone時は `GIT_TERMINAL_PROMPT=0` / `GCM_INTERACTIVE=never` を export する。
**非公開リポジトリのURLを渡すとgitが資格情報の入力を待って固まる**ことを実測したためで、
AIエージェントから呼ばれる前提のスクリプトでは、待たされるより即座に失敗するほうがよい
（認証自体はこのスクリプトの責務ではなく、gitの資格情報ヘルパ任せである）。

仕様の詳細は
[.claude/docs/spec/answer-talker.md](../spec/answer-talker.md)「正解ソースの取得」節を正とする。

## 却下した案

- **常にcloneして読む場所を1つに揃える**（当初の素案）。取得後の扱いが一本化され、
  「正解は必ず一時ディレクトリにある」と言い切れるため後始末も単純になる。しかし上記のとおり
  **`--depth 1` が効かず**、**素のディレクトリでは失敗する**。要件を満たせない。

- **ローカルパスのうち、gitリポジトリのものだけcloneする**（素のディレクトリはそのまま読む）。
  「浅くならない」問題は残ったまま、**分岐が3通りに増える**（URL／ローカルgit／ローカル素）。
  読む場所が2通りある点は結局解消せず、後始末の判断も複雑になる。得るものが無い。

- **ローカルパスを一時ディレクトリへコピーする**（cloneではなく `cp -r`）。読む場所は揃い、
  元を書き換える心配も無くなる。しかし正解の規模は未知であり、大きなリポジトリのコピーは
  時間とディスクを無駄に消費する。**そもそも書き換えないのだから、コピーする必要が無い。**
  「元を守る」目的なら、サブエージェントへWrite/Editを渡さないことで既に達成されている。

- **後始末を `trap` だけに任せる**（`cleanup` サブコマンドを持たない）。行数は減る。しかし
  `trap` はスクリプトのプロセス内でしか働かず、`resolve` と実際のレビューが**別のプロセス**で
  行われる本スキルの構成（スキルが手順ごとにコマンドを実行する）では機能しない。
  後始末を手順の明示的な1ステップにするため、サブコマンドとして外へ出した。
