# 0054. Gemini CLIのサブエージェントは保存のみとし集計しない

## 背景

DDR 0022（issue #23）は、Gemini CLI について **「ミラーへの保存は維持し、対応工数の集計対象に
含めることはスコープ外とした。」** と決めていた。この境界は、集計側
`_usage_aggregate_and_merge_subagents` の glob が `subagents/agent-*.jsonl` であるのに対し、
Gemini分を `subagents/<session_id>/` という1階層下へ置くことで、**追加のガード条件を書かずに
構造だけで保証される**という形で実装されている。

issue #97 は、このうち**メインセッション分について決定を覆した**（`main.jsonl` を集計入力に
した）。そこで、サブエージェント分をどうするかを改めて決める必要が生じた。

## 決定

**Gemini CLI のサブエージェントは、従来どおり保存のみとし、対応工数の集計対象に含めない。**
`subagents/<session_id>/` へ1階層下げてミラーする現行の構造も変えない。

**DDR 0022 の「Gemini CLI対応の扱い」は、この部分については引き続き有効である。**
issue #97 が覆したのはメインセッション分だけであり、0022 全体が無効になったわけではない。

## 理由

- **メインセッションの集計だけで issue #97 の受け入れ条件を満たす。** issue #97 が求めている
  のはツール実行回数・ツールエラー回数・応答回数・使用モデル・稼働時間・トークンの集計であり、
  いずれもメインセッションのログから得られる。サブエージェントまで広げる必然性が無い。
- **実機で検証できない範囲を増やしたくない。** このリポジトリの開発機に `~/.gemini` は存在せず、
  issue #97 の検証は合成フィクスチャに留まっている。サブエージェントのネスト構造は本体実装
  （`chatRecordingService.ts`）のコードレビューで裏付けたにすぎず、**実際のディレクトリ構造を
  1度も見ていない**。未検証の前提の上にさらに集計ロジックを積むと、誤りが表面化したときの
  切り分けが難しくなる。
- **現行の構造的な保証が壊れない。** glob が一致しないことで集計外が保証されている状態は、
  ガード条件の書き忘れという失敗モードを持たない。集計対象に含めると、この保証を明示的な
  条件分岐へ置き換えることになり、条件の抜けが混入する余地が生まれる。
- **必要になったら後から広げられる。** 保存は続けているので、実機で構造を確認できた時点で
  過去のログも含めて集計対象にできる。逆（集計してから戻す）は数値の連続性が壊れる。

## 却下した案

| 案 | 却下理由 |
|---|---|
| メインと同じ畳み込みでサブエージェントも集計する | 実機未検証のディレクトリ構造に依存する範囲が増える。issue #97 の受け入れ条件も求めていない |
| `ToolCallRecord.agentId` を使い、親セッション側からサブエージェント分を辿って集計する | `agentId` が実データでどう入るかを確認できていない（合成フィクスチャでしか触れていない）。同じ理由で見送り |
| Gemini分のサブエージェントログをミラーすること自体をやめる | 将来集計対象にする余地を失う。保存のコストは低い |
| DDR 0022 に `status: superseded` を付ける | 0022 の主題は「push断面を全文コピーから行番号インデックスへ置き換える」ことであり、Gemini の集計対象外はその一部にすぎない。DDR全体が無効になったわけではないため `superseded` は過剰である。代わりに**本DDRから0022を参照し、どの部分が生きていてどこが置き換わったかを明示する**形を採った |

## 影響

- `_usage_sync_session_logs` の Gemini 分岐（`subagents/<session_id>/` へディレクトリごとコピー）は
  変更しない。
- `_sync_usage_state_gemini` は `_usage_aggregate_and_merge_subagents` を呼ばない。
- 同関数のコメントにあった「Geminiのログは保存するが対応工数の集計対象にはしない」という記述は、
  主語が広すぎて**メインセッションについては誤り**になったため、issue #97 で書き換えた
  （サブエージェントについての説明は正しいので残している）。
- 仕様: `.claude/docs/spec/issue-mr-workflow.md`「エンジン判定」節・「対応工数レポート」節。
