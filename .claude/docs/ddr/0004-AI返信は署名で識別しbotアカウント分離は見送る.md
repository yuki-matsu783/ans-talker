# 0004. AIエージェントのレビュー返信は本文への署名で識別し、botアカウント分離は見送る

## 背景

issue駆動MRワークフロー支援（PR #4）で、AIエージェントが `reply` サブコマンド
（`Add-MrThreadReply`）を使ってレビュースレッドに返信する機能を追加した際、レビューで
「AIが返信すると、GitHub上は投稿者アカウントが元コメントの投稿者（`gh` CLIの認証ユーザー＝
人間自身）と同一に見えてしまい、誰が書いた返信か判別できない」という指摘を受けた
（`PRRT_kwDOT4Y-5s6ZfGaK`, PR #4）。

## 決定

**返信本文の先頭に `Claude Codeより:` という署名行を必ず付ける運用ルールを採用する。**
GitHub/GitLab上の投稿者アカウント自体は分離せず、本文側でAIによる返信であることを明示する。

`Add-MrThreadReply` 関数自体は変更しない（`-ReplyBody` は呼び出し側が組み立てた自由文を
そのまま渡す、という既存の決定と矛盾しない）。署名の付与は `.claude/skills/issue-mr-flow/SKILL.md`
の `reply` サブコマンド手順（呼び出し側）の責務とする。

## 却下した案

- **botアカウントによる投稿者分離**: 専用のGitHub bot/machineアカウントを作成し、そのPATを
  `Add-MrThreadReply`（`Github.ps1`/`Gitlab.ps1`）で使うよう認証を切り替える案。GitHub UI上で
  本当に別アカウントとして表示される根本解決にはなるが、botアカウントの作成・PAT管理
  （保管場所・ローテーション）・GitHub/GitLab双方での認証切り替え実装が必要になり、
  本PR（issue #3）の規模を大きく超えるため見送った。将来的に必要になれば別issueとして
  起票する。
- **見送り・未決定事項として記録するのみ**: 実装コストはゼロだが、レビュアーの指摘に対して
  具体的な改善を示せないため不採用。

## 検討の経緯

3案をユーザー（プロジェクトオーナー）に提示して確認した結果、署名方式を採用した。詳細な
比較検討は `worklog/20260815_pr4-review-followup2.md`（設計反映時に削除済み）を参照していたが、
削除後は本DDR（旧ADR）が唯一の記録となる。
