# 0051. Gemini集計はrewindToを読み飛ばしメッセージを削らない

## 背景

Gemini CLI v0.39.0 以降のセッションログには、`/rewind` 操作の記録として
`{"$rewindTo": "<messageId>"}` というレコードが現れる。CLI本体はこれを読んで、会話履歴を
そのメッセージの時点まで**切り詰めて再構成**する。

issue #97 でこのログを対応工数レポートの集計対象にするにあたり、集計側も同じように切り詰める
べきかを決める必要があった。旧 `.json` 形式では `/rewind` は配列を切り詰めて保存していたため、
**ファイル上に痕跡が残らなかった**（＝集計側で扱いようがなかった）。新形式で初めて選択肢が
生まれた論点である。

## 決定

**`$rewindTo` レコードは読み飛ばすだけとし、メッセージを削らない。** 巻き戻された範囲の
トークン・ツール実行・応答回数も、そのまま対応工数として計上する。

## 理由

- **対応工数レポートが測っているのは「かかった手間」であって「残った会話」ではない。**
  巻き戻された範囲でも、APIは呼ばれ課金は発生し、ツールは実際に実行され、人間はその応答を
  読んでいる。会話履歴から消えたことは、その工数が発生しなかったことを意味しない。
- **むしろ巻き戻しが起きた区間こそ手間がかかっている。** 試行錯誤して戻したという事実は、
  工数の観点では加点要因であり、これを削ると「うまくいかなかった作業ほど工数が小さく見える」
  という逆の歪みが生まれる。
- **切り詰めを実装すると畳み込みが複雑になる。** `$rewindTo` は「そのidより後を捨てる」という
  順序依存の操作であり、id単位の後勝ちマージ（DDR 0050）と組み合わせると、どの時点の順序を
  正とするかを別途決める必要が出る。得られるものに対して複雑さが見合わない。

## 却下した案

| 案 | 却下理由 |
|---|---|
| CLI本体と同じく、`$rewindTo` の時点まで切り詰めて集計する | 発生した課金・ツール実行・人間の作業時間を計上から落とすことになり、レポートの目的（かかった手間の把握）に反する |
| 巻き戻された分を別枠（「巻き戻し分」）として分けて表示する | レポートの列が増える割に、読み手が取れる行動が無い。必要になったら後から足せる |
| `$rewindTo` の出現回数だけを指標として記録する | 対応工数の指標として何を意味するかが定まらない。issue #97 の受け入れ条件にも無い |

## 影響

- `_usage_gemini_fold` のレコード振り分けで、`$rewindTo` を持つ行は `empty` を返して読み飛ばす
  （`.claude/hooks/lib/UsageTracking.sh`）。
- `.claude/scripts/test/test_usage_tracking.sh` に「`$rewindTo` 後のメッセージも残る」ケースがある。
- 仕様: `.claude/docs/spec/issue-mr-workflow.md`「対応工数レポート」節。
