# 0065. 対応付けと禁止語の材料は受講者ソース全体へ広げる

## 背景

issue #6 で受講者ソース全体が手に入るようになった。これに伴い、受講者側を材料にしている
2箇所の範囲を広げるかどうかを決める必要があった。

1. **`answer-talker-map.sh` の対応付けの左辺。** 従来は「受講者の**変更**ファイル」対
   「正解の**全**ファイル」だった。受講者リポジトリに既にあるが今回のMRで触っていない
   ファイルは、`matched` にも `submissionOnly` にも現れない。
2. **`answer-talker-spoiler-check.sh` の禁止語から差し引く材料。** 従来は「受講者diffに
   現れる語」だった（禁止語 = 正解の識別子 − 受講者diffの語 − 除外語 − 3文字以下）。

2 については、DDR 0061 が
「**誤検知の側へ倒す**（正当な指摘を落としてでも転記の見逃しを避ける）」と決めている。
材料を広げることがこの方針を弱めないかを確かめる必要があった。

**実測で答えが出た。** 正解の識別子 `read_lines` を含む指摘だけが drop され、受講者側の語を
使った指摘・識別子を含まない指摘は残った。つまり材料が diff からしか作られない状態では、
**受講者が hunk外で同じ関数を既に持っていても、その識別子を含む指摘は drop される**。
issue #6 が可視化しようとした「hunk外の責務」についての指摘が、まさに落ちる向きに働いていた。

## 決定

1. **両方の範囲を受講者ソース全体へ広げる。** ただし**どちらも省略可能な引数
   （`--submission-root`）で切り替える形にし、省略時は従来の挙動に一致させる。**
   DDR 0062 の段3（取得できなかった場合）で通るのがこの経路である。

2. **どちらで動いたかを機械可読なキーで返す。** 対応付けは `scope`、ネタバレ検査は
   `materialScope`（いずれも `full` / `diff`）。理由は
   DDR 0063。

3. **`submissionOnly` の意味が変わることを、意味づけではなくキーで表す。**

   | `scope` | `submissionOnly` の意味 |
   |---|---|
   | `full` | **正解に無いファイル** |
   | `diff` | 今回のMRで追加したファイル |

   サブエージェント定義がこの値を見て読み方を変える。**同じキー名で意味だけが変わる状態を
   放置しない**（`referenceOnly` を「まだ作っていない分割単位」の候補として読む手順が、
   `scope` によって成立したりしなかったりするため）。

4. **DDR 0061 は無効化しない。方針は維持されている。** 材料を広げることは**差し引く量を
   増やす**だけであり、禁止語は減りこそすれ増えない。したがって効くのは**誤検知が減る方向のみ**で、
   転記の見逃しが増えることはない。0061 が守ろうとした「見逃しより誤検知を許容する」という
   非対称は、そのまま保たれる。

5. **`--submission-root` に存在しないパスが渡された場合はエラーにする。** 黙って無視すると
   `materialScope` が `diff` へ戻り、**広げたつもりで広がっていない状態が正常応答として返る**。

## 却下した案

- **材料を広げない（従来どおり diff から作る）。** 最も変更が小さく、0061 との関係を
  考えずに済む。しかし上記のとおり、**issue #6 の目的である「hunk外の責務についての指摘」だけが
  選択的に落ちる**。機能を追加した結果、その機能が生む指摘だけが届かないという形になる。
- **範囲を広げたうえで、`--submission-root` を必須にする。** 引数の省略で従来挙動へ戻る道を
  塞ぐと、段3（受講者ソースを取得できなかった場合）に呼べる形が無くなる。縮退を持つ設計と
  噛み合わない。
- **禁止語の除外語（`ATR_STOPWORDS`）を拡充して誤検知を減らす。** 材料を広げる代わりに
  除外語で調整する案。**0061 の方針を無言で反転させる**——除外語は「正解の識別子であっても
  禁止語にしない」という指定であり、拡充すれば見逃しが増える方向に効く。誤検知を減らす手段として
  材料の拡張と同じに見えるが、効く向きが逆である。
- **対応付けだけ広げ、禁止語の材料は据え置く。** 変更を1つに絞る案。しかしこの組み合わせが
  最も悪い——`submissionOnly` が広がって新しい指摘が生まれる一方、その指摘に含まれる識別子は
  依然 diff からしか差し引かれないため、**新しく生まれた指摘ほど drop されやすい**。
