## 検証

```bash
# 1. frontmatterインデックスを再生成し、新規DDRが載ることを確認する
bash .claude/scripts/src/extract-frontmatter.sh .
bash .claude/scripts/src/search-frontmatter.sh --type ddr | tail -6

# 2. DDR番号の重複が無いことを確認する（mainとの突き合わせ）
#    キーは `ddrDuplicates` ではなく `duplicateDdrNumbers`。jqの `{key}` 短縮形は存在しない
#    キーをエラーにせず null で返すため、名前を誤ると重複の有無に関わらず null になり空振りする
bash .claude/scripts/src/check-base-conflicts.sh \
  | jq -c '{hasConflict, hasDuplicateDdrNumber, duplicateDdrNumbers}'
bash .claude/scripts/src/check-base-conflicts.sh \
  | jq -e '.hasDuplicateDdrNumber == false' > /dev/null && echo 'DDR番号の重複なし'

# 3. specの記述を関数名で機械的に照合する
#    334行の github_filter_findings_by_valid_lines は issue #77 のchangelogとして
#    **1件残っているのが正しい**（0件になっていたら過去の記録を壊している）
printf 'github_filter_findings_by_valid_lines: %s  # 1（issue #77 の表）であること\n' \
  "$(grep -c 'github_filter_findings_by_valid_lines' .claude/docs/spec/adversarial-review.md)"
for f in valid_ranges_from_patches gitlab_valid_ranges_from_diffs_json allow_old_line; do
  printf '%s: %s\n' "$f" "$(grep -c "$f" .claude/docs/spec/adversarial-review.md)"   # 1以上であること
done

# 4. 空行2連続・末尾改行の確認（変更した全mdに対して）
awk 'prev=="" && $0=="" {print FILENAME": "NR} {prev=$0}' .claude/docs/spec/*.md .claude/docs/ddr/*.md
```

**2・3は「異常があるときに本当に検出できるか」を満たす形にしてある**（件数・真偽値を出す）。
**3から「0件であること」を期待する検査は外した。** 今回の正しい期待値は「issue #77 の表に
**1件残っている**」であり、0件はむしろ履歴を壊した状態を意味する。観点表の「検証コマンドが
空振りしないか」への対応。
